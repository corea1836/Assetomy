# PRD: assetomy

## 목표
계좌 연동 없이 카드 이용내역 파일만으로, 흩어진 카드 지출을 한 화면에서 보고 확인이 필요한 지출(정기결제·중복 결제 의심·고액 결제)을 찾게 한다.

> **"계좌 연동 없이, 카드 이용내역 파일만으로 확인할 지출을 찾아준다."**

MVP는 **랜딩 → 데모 → 로그인 → 대시보드 → 결제 → 배포** 한 사이클을 완주하고, 아래 가설(H1~H5)을 검증할 지표를 확보하는 것이 목표다. 실제 절감액 계산과 카드 추천은 배포 후 다시 기획한다.

## 사용자
| | P1. 월말 현타형 직장인 | P2. 구독 정리형 |
|---|---|---|
| 상황 | 카드 2~3장, "이번 달 왜 이렇게 많이 썼지?" | "뭐가 매달 빠져나가는지 모르겠다" |
| 원하는 것 | 흩어진 카드 지출을 한 화면에서 | 잊고 있던 정기결제를 찾아 끊기 |
| 역할 | Free 활성화 | Pro 전환의 핵심 타깃 |

## 지원 범위
- 한국 카드사의 **신용카드 이용내역(승인내역)** 파일만 받는다. 체크카드·은행 거래내역·청구서는 받지 않는다. 예외로 현대카드 앱·웹의 명세서 "이용 내역" 화면을 PDF로 저장한 파일은 프로필로 받는다(ADR-019).
- 한 파일은 한 카드의 내역이어야 한다. 사용자가 파일마다 카드(사용자 라벨)를 지정하고, 카드별로 구분해 합산한다. 카드 전체 번호는 받지 않는다.
- 검증된 카드사 형식(프로필)은 코드로 바로 읽는다. 초기 프로필은 익명화한 실제 파일로 검증한 카드사 2종이다. 첫 프로필은 현대카드 명세서 PDF다.
- 프로필이 없는 형식은 Claude가 컬럼 매핑을 제안하고, 사용자가 미리보기를 보고 확인하면 같은 코드로 읽는다(폴백). 확인한 매핑은 같은 형식의 다음 업로드에 다시 쓴다. 폴백은 취소를 음수 금액으로 표시한 형식만 읽는다. PDF는 열 이름이 없어 폴백이 없고 프로필로만 읽는다.
- 모든 거래 행에 승인번호 등 거래별 식별자가 있어야 한다. 없으면 지원하지 않는 형식으로 안내한다. 예외로 식별자가 없는 현대카드 명세서 PDF는 거래 내용(이용일·가맹점·금액·같은 내용 안 순번)으로 식별한다(ADR-006).
- 파일은 .csv(UTF-8/EUC-KR)·.xlsx·.pdf를 받고, 파일당 4MB·5,000행(PDF는 100쪽)까지다. PDF는 글자를 추출할 수 있는 파일만 받는다(스캔 이미지·암호 PDF 제외). 날짜에 연도가 있는 형식만 받는다.
- 현대카드 명세서 PDF는 상단 명세서 금액과 거래 금액 합이 정확히 같을 때만 저장한다. 일시불이 아닌 거래(할부 등)나 "취소" 표시 행이 있거나 합계가 다르면 UNREADABLE이다. 음수 금액은 취소·환불로 읽는다.
- 할부는 이용일에 원금 전액을 지출로 잡는다. 회차별 금액만 있는 형식은 실제 파일을 확인한 뒤 프로필에서 처리한다.
- **[확정 필요]** 초기 프로필의 나머지 카드사 1종과 .xls 지원 여부는 실제 파일을 확인한 뒤 확정한다.

| 11 월간 재방문 | 다음 달 파일 추가 | 새 거래만 반영 |
| 12 구독 해지 | Polar 포털 | 기간 종료 후 Free |
| 13 전체 삭제 | 설정에서 전체 삭제 | DB의 소비 데이터는 즉시 삭제. 원본은 즉시 삭제를 시도하고, 남은 파일은 정기 정리로 비워짐 |
| 14 처음 보는 형식 | 프로필 없는 형식 업로드 → 매핑 제안 → 미리보기 확인 | 실제 셀 값은 외부로 보내지 않음. 확인한 매핑으로 합계 일치. 같은 형식은 다음부터 확인 생략 |

## 플랜별 기능
| 기능 | 데모 | Free | Pro |
|---|---|---|---|
| 월별 스냅샷(월 선택, 총지출·카테고리·Top N·일별, 반영 기간) | ✓ | ✓ | ✓ |
| 전월 대비 총액(진행 중인 달·전월 데이터 없는 달·카드 내역이 두 달을 다 덮지 않는 달 제외) | ✓ | ✓ | ✓ |
| 정기결제 · 중복 결제 의심 · 고액 결제 탐지 | 상세 | **건수 · 합계만** | 상세 |
| 여러 달 누적 추세(최대 12개월) | ✓ | 잠금 카드 | ✓ |
| AI 월간 요약 | 고정 텍스트 | ✓ Sonnet(Free에 보이는 집계만) | ✓ Opus(탐지 상세·추세 포함) |
| 가맹점 카테고리 수정 | ✗ | ✓ | ✓ |
| 업로드 · 원본 보관 · 삭제 | ✗ | ✓ | ✓ |

- 가격: Pro **$4.99/월**(Polar 기본 통화 USD)에 KRW 가격을 함께 둔다. 랜딩·모달은 KRW로 표시하고, 실제 결제 통화는 Polar가 고객 위치로 정한다. **[확정 필요]** KRW 금액(sandbox는 임시값).
- AI 월간 요약은 그 달의 기간·건수·총지출과 비중이 큰 카테고리, 전월 대비를 숫자와 함께 2~3문장으로 요약하고, 사용자가 바로 해 볼 수 있는 절약 팁 1~5개(보통 3~5개)를 준다(예: 비중이 가장 큰 카테고리의 다음 달 예산 정하기, 자주 결제한 가맹점의 횟수 정하기, 정기결제가 아직 쓰는 서비스인지 점검, 카드사 앱에서 중복 청구인지 확인). Pro는 전월 데이터가 있는 완료된 달이면 지난달보다 가장 많이 늘어난·줄어든 카테고리를 금액 차이와 함께 짚고, 가장 많이 늘어난 카테고리의 절약 팁을 준다. 팁은 입력 집계에서 근거를 찾고, 금융상품을 추천하지 않는다.
- 전월 대비는 두 달 중 한 달에라도 거래가 있는 카드마다 첫 거래일~마지막 거래일이 지난달 1일부터 선택한 달 말일까지를 덮을 때만 계산한다(앞뒤 3일 여유). 명세서 이용 기간은 카드·결제일마다 달라서(예: 12일~다음 달 11일) 한 장만 올리면 첫 달은 중간부터 시작하고, 이용 내역 파일에는 그 기간이 적혀 있지 않아 거래일로 판단한다. 덮지 않으면 총지출 카드에 "N월 내역이 일부만 있어 지난달과 비교하지 않았어요"를 보여주고, Pro 추세의 카테고리 변화와 AI 요약의 전월 대비도 빠진다.
- Free 요약은 Free 화면에 보이는 정보(스냅샷·전월 대비·티저의 건수·합계)만 입력으로 만든다. 탐지 상세·추세는 넣지 않는다. 플랜이 바뀌면 그 달 요약을 다시 만든다.
- 잠금 카드는 blur 없이 설명과 정적 예시로 만든다.
- 탐지가 0건이면 "이번 규칙으로 확인할 지출 후보가 발견되지 않았어요"를 보여준다.
- 티저는 종류별 건수·금액과, 후보 거래를 한 번씩만 센 `candidateTotal`을 표시한다. 동일 거래가 여러 탐지에 걸려도 통합 금액에 중복 합산하지 않는다. 정기결제 금액은 선택 월의 결제액이다.
- 표현 규칙: "확인이 필요한 지출", "중복 결제 의심"처럼 쓴다. 정기결제·중복 의심·고액 결제는 정상 지출일 수 있으며 실제 절감액을 뜻하지 않는다. 절감 보장이나 부정 결제 확정 표현을 쓰지 않는다(AI 요약 포함). AI 요약과 팁의 숫자는 AI가 자리표시자로 쓰고 코드가 입력 집계 값으로 채운다. AI가 숫자를 직접 쓰거나 계산하지 않고, 아낄 수 있는 금액을 약속하지 않는다.
- 운영 한도: 사용자당 최근 24시간 업로드 시도 30개, 동시 처리 2개, 파일당 4MB. 파일 선택 화면에 안내하고 서버에서 강제한다.

## 카테고리
- 고정 14개: 식비, 카페·간식, 배달, 교통, 쇼핑, 마트·생활, 구독·정기결제, 주거·통신, 의료·건강, 문화·여가, 여행·숙박, 교육, 금융·보험, 기타.
- 사용자가 가맹점의 카테고리를 바꾸면 그 사용자의 같은 가맹점 거래 전체와 다음 업로드에 적용하고, 숫자는 즉시 다시 계산한다. 요약은 집계가 바뀌면 다음 조회 때 다시 만든다.
- 새 거래의 카테고리는 사용자 수정값 → 기존 거래의 같은 가맹점 → Claude 분류 순서로 정한다. 분류에 실패하면 '기타'다.

## 데이터 보관
- 원본 파일은 서버에서 암호화한 뒤 저장한다. 같은 파일·실패로 끝난 업로드의 원본은 정기 정리로 곧바로 지운다.
- 거래·요약은 이용일 기준 12개월이 지나면 플랜과 관계없이 지운다. 원본은 그 파일의 마지막 거래를 기준으로 센다. 이용일이 12개월보다 오래된 거래는 저장하지 않는다.
- 업로드 삭제·전체 삭제는 즉시 처리한다. 전체 삭제는 계정·구독을 유지한다.
- 탈퇴하면 데이터와 계정을 즉시 지운다. 자동 갱신 예정인 구독이 있으면 먼저 해지하도록 안내하고, 해지 예약 상태면 남은 기간이 사라진다고 알린 뒤 진행한다.

|---|---|---|---|---|
| H1 가치 | "연동 없이 파일만으로"에 반응한다 | 랜딩의 데모 클릭 방문자 / 랜딩 방문자, 동일 일자 기준 주간 집계 | 페이지뷰 + `demo_click`. 로그인 진입도 별도 집계 | 방문자 100명 이상에서 데모 클릭률 20% 이상 |
| H2 마찰 | 첫 업로드가 활성화의 주요 마찰이다 | 첫 서버 업로드 시도 후 24시간 내 거래 저장에 성공한 사용자 / 첫 시도 사용자 | `user_metrics`의 첫 시도·첫 성공, `upload_attempts`의 단계·결과·코드 | 관찰 완료 사용자 30명 이상에서 성공률 80% 이상 |
| H3 전환 | 후보 지출 티저와 추세가 결제 동기다 | 첫 업그레이드 클릭 후 7일 내 첫 실결제 사용자 / 첫 클릭 사용자, source별 집계. 티저 노출→클릭률도 별도 측정 | `user_metrics`의 노출·첫 클릭·source·첫 결제. Polar production의 active Pro 첫 확인 | 관찰 완료 클릭 사용자 100명 이상에서 전환율 5% 이상 |
| H4 습관 | 명세서 주기에 맞춰 재방문한다 | 첫 성공 후 30~45일에 기존 최종 거래일보다 뒤의 거래를 추가한 사용자 / 첫 성공 후 45일이 지난 사용자 | 삭제와 독립적인 `upload_attempts` 완료 이력과 `extends_period` | 관찰 완료 사용자 30명 이상에서 20% 이상 |
| H5 신뢰 | 해석이 정확해야 계속 쓴다 | 성공 24시간 내 사용자 삭제 업로드 / 24시간 관찰 완료 성공 업로드. UNREADABLE / 파싱 단계에 도달한 업로드 | `upload_attempts`의 완료·삭제 시각·실패 단계 | 각 분모 30건 이상에서 두 비율 각각 10% 이하 |

- 목표치는 초기 운영 가설이다. 관찰 기간과 최소 표본이 채워지기 전에는 성공·실패를 단정하지 않고, 바꿀 때는 적용일과 이유를 남긴다.
- Vercel Analytics의 페이지뷰·커스텀 이벤트는 탐색용이다. 기본 방문자 식별이 24시간 후 폐기되므로 여러 날에 걸친 전환·재방문은 DB 이력(`user_metrics`, `upload_attempts`)으로 측정한다.
- `user_metrics`는 첫 시도·첫 성공·티저 첫 노출·첫 업그레이드 클릭과 source·첫 실결제만 저장한다. source는 `teaser/trend/summary/pricing/settings` 허용목록이며 **첫 클릭 기준 귀속**으로 고정한다. 첫 클릭이 없으면 `direct`로 기록한다. H3의 클릭 분모는 클릭 당시 Free 사용자이고, 결제 시각은 그 클릭 이후여야 한다.
- 첫 실결제는 production에서 Pro 상품의 active 구독을 처음 확인한 시각이다(쿠폰·무료 구독을 운영하지 않는 전제). sandbox·mock은 제외한다.
- `upload_attempts`는 서버가 업로드를 받은 시점부터 파싱·매핑 확인·저장·사용자 삭제 결과를 남긴다. 재처리는 같은 attempt를 갱신하고, 새로 올린 파일은 새 attempt다. no_new는 첫 활성화 성공으로 세지 않는다.
- 거래·파일명·가맹점·카드번호를 Analytics나 측정 이력에 넣지 않는다. 전체 데이터 삭제 시 사용자의 측정 이력도 삭제하며, 삭제 이전 관찰은 코호트에서 제외한다. 이후 새로 업로드하면 새 코호트로 관찰한다.

## MVP 제외 사항
- 실제 절감액 계산, 카드 추천(배포 후 재기획)
- 계좌·카드사 연동(스크래핑, 오픈뱅킹)
- 체크카드·은행 거래내역·청구서, 거래별 식별자가 없는 카드사 형식(현대카드 명세서 PDF 제외), 여러 카드가 섞인 파일, UTF-16 CSV
- 프로필이 없는 PDF, 스캔 이미지 PDF(OCR), 암호가 걸린 PDF
- 원화 외 통화 금액(해외 현지금액은 쓰지 않고 원화 금액만 쓴다)
- 재방문 알림(이메일·푸시)
- 카테고리 추가·이름 변경(고정 14개만 쓴다)
- 다크 모드, 다국어
