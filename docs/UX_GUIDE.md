# UX 가이드

Figma의 [UI 디자인 원칙](https://www.figma.com/ko-kr/resource-library/ui-design-principles/)(원칙 7가지 · 프로 팁 4가지)을 assetomy의 여정과 가설(H1~H5)에 맞게 옮긴 규칙이다. 목표는 두 가지다. 처음 온 사람이 데모와 가입까지 오게 하고, 화면마다 다음 단계 하나로 자연스럽게 넘어가게 한다.

- 이 문서는 화면이나 기능을 새로 정의하지 않는다. 범위는 `PRD.md`, 화면과 분기는 `USER_FLOW.md`, 토큰·컴포넌트·문구는 `DESIGN.md`가 정한다. 이 문서는 그 안에서 무엇을 먼저 보여주고 어디로 이끌지 정한다. 충돌하면 위 문서를 따르고 차이를 보고한다.
- 마지막의 "개선 후보"는 step 파일이 지시할 때만 구현한다.

## 원칙
1. **화면마다 다음 단계는 하나다.** 사용자가 여정의 어디에 있는지로 다음 단계를 정하고, 그 행동이 화면에서 가장 눈에 띄게 한다.
2. **질문에 먼저 답하고, 그다음에 권한다.** 사용자가 이 화면에서 품는 질문(USER_FLOW 여정 맵)의 답을 첫 화면에 두고, 다음 행동은 답 바로 아래에 둔다.
3. **유도하되 재촉하지 않는다.** 신뢰가 전환보다 먼저다. 가치가 가려진 자리에서만 권하고, 시간 압박·과장·불안 조성을 쓰지 않는다.
4. **숫자를 사용자가 검증할 수 있게 한다.** 숫자 옆에 반영 기간·거래 건수를 붙여 카드사 앱과 맞춰 볼 수 있게 한다. 이 확인이 aha이고 재방문 이유다.

## 상태별 다음 단계
다음 단계는 페이지가 아니라 사용자 상태로 정한다.

| 사용자 상태 | 화면 | 먼저 보여줄 답 | 다음 단계 | 보조 출구 | 지표 |
|---|---|---|---|---|---|
| 처음 방문 | `/` | 연동 없이 파일만으로 확인할 지출을 찾아준다 | 데모 보기 | 무료로 시작하기 · 로그인(텍스트) | H1 |
| 데모 보는 중 | `/demo` | 실제와 같은 대시보드(예시 데이터) | 내 이용내역으로 해보기 | 랜딩 | 로그인 진입 |
| 로그인 전 | `/login` | 구글 1클릭, 받지 않는 정보 | Google로 계속하기 | - | - |
| 거래 없음 | 빈 대시보드(온보딩) | 어떤 파일을 어디서 받는지 | 파일 선택 | 카드사별 가이드 | H2 |
| 업로드 중 | 업로드 상태 행 | 파일별 상태와 결과 한 줄 | 실패·확인 필요 행의 행동 버튼 | 틀렸어요 | H2 · H5 |
| 1개월치만 있음 | 대시보드 | 총지출 · 반영 기간 · 카테고리 | 새 이용내역 추가("한 달치만 더 올리면…") | 카테고리 수정 | H2 · H3 |
| Free, 2개월 이상, 후보 있음 | 대시보드 | 총지출 → 후보 지출 티저 | 티저의 Pro로 보기 | 추세 잠금 카드 · 요약의 Pro로 보기 | H3 |
| Free 후보 0건 · Pro · 재방문 | 대시보드 | "N월까지 반영됨" · 전월 대비 | 새 이용내역 추가 | 월 선택 · 카테고리 수정 | H4 |

- 1개월치 사용자의 다음 단계는 결제가 아니라 데이터 추가다. 정기결제·추세는 2개월 이상에서 나오므로, 먼저 가치를 보게 한 뒤 권한다.

## 여정별 설계

### 유치: 랜딩 (`/`) — H1
이탈 원인: "내 금융정보를 넘겨도 되나", "뭘 해주는지 모르겠다".
- 히어로는 5초 안에 세 가지를 전한다: 무엇을(흩어진 카드 지출 + 확인이 필요한 지출) · 어떻게(파일만, 연동 없음) · 다음(데모 보기, 로그인 없이).
- 히어로의 다음 단계는 "데모 보기" 하나다. 아직 신뢰가 없는 사람에게 가입부터 요구하지 않는다. "무료로 시작하기"는 가격 밴드와 마지막 CTA 밴드에 둔다.
- 기능 쇼케이스 3줄은 반론 하나에 하나씩 답한다: 카드가 흩어져 있다 → 한 화면, 무엇을 봐야 하나 → 확인이 필요한 지출, 안전한가 → 연동 없음·언제든 삭제. 줄마다 글 옆에 그 답을 보여주는 그림을 둔다.
- 9월 요약 밴드는 "뭘 해주는지"에 답한다. 월간 요약 문장 옆에 그 근거 숫자를 두어, 문장은 AI가 쓰고 숫자는 코드가 계산한다는 것을 함께 보여준다.
- 목업 수치는 데모 fixture와 같다(DESIGN). 데모에서 같은 숫자를 다시 보면 실제 화면이라고 믿는다.
- 기능 밴드 다음에 "이렇게 시작해요" 3단계(이용내역 받기 → 카드 고르기 → 올리고 확인하기)를 둔다. 가입 전에 "파일을 구할 수 있나" 불안을 풀고, 청구서가 아니라 이용내역이라는 점을 미리 알린다(H2).
- 쓰지 않는다: 진입 팝업, 이메일 수집, 자동 재생, 가입 전 정보 입력.

### 데모 (`/demo`) → 가입
이탈 원인: "내 데이터로는 와닿지 않는다", 가입 후 Free 화면이 데모와 달라 실망함.
- 데모는 실제 대시보드와 같은 컴포넌트를 쓴다. 데모가 약속한 화면이 가입 후 화면이다.
- 첫 줄에 예시 데이터임을 밝히고, "내 이용내역으로 해보기"는 헤더에 고정해 어디서든 찾을 수 있게 한다.
- 데모는 Pro 화면이다. 탐지 영역 앞에 Pro 구분선을 두어 Free에서 보이는 범위(건수·합계)를 미리 밝힌다(H3).
- 끝까지 본 사람을 위해 맨 아래에 다시 "내 이용내역으로 해보기" 구역을 둔다. 위로 올라가 버튼을 찾게 하지 않는다.

### 가입 (`/login`)
- 구글 버튼 하나만 둔다. 받지 않는 것을 한 줄로 밝힌다("카드번호·계좌·카드사 비밀번호는 받지 않아요").
- 버튼 모양과 문구("Google로 계속하기")는 Google 브랜드 가이드를 따른다(DESIGN "구글 로그인 버튼"). OAuth 앱 검증 요건이다.
- 로그인 뒤 `next`로 돌아간다. 사용자가 누른 행동이 로그인 뒤에 이어져야 한다(데모 → 대시보드, 가격의 Pro 시작하기 → 업그레이드 모달).
- `?error`는 원인과 "다시 시도"를 함께 보여준다.

### 활성화: 빈 대시보드 → 첫 업로드 — H2
이탈 원인: 파일을 못 구함, 청구서를 받아 옴, 카드 지정이 헷갈림, 처리 실패.
- 빈 대시보드의 목표는 첫 파일 하나다. 빈 차트나 0원 카드를 그리지 않고 온보딩만 보여준다.
- 온보딩은 3단계로 나눈다: ① 카드사에서 이용내역 받기 ② 파일마다 카드 고르기 ③ 올리기. "청구서 말고 이용내역(승인내역)"은 ① 안에서 `font-semibold`로 강조한다.
- 카드사별 가이드는 접어 두고(`<details>`) 사용자가 고른 카드사만 펼친다.
- "최근 3개월치"를 권한다. 이유: 2개월 이상이어야 정기결제·추세가 나와 첫 대시보드에서 바로 확인할 지출을 본다.
- 카드는 파일마다 사용자가 직접 고른다. 자동으로 고르지 않는다. 이유: 잘못 지정하면 삭제 후 다시 올려야 한다(UC-06·07). 새 카드 라벨은 그 자리에서 만든다(placeholder "예: 신한 생활비").
- 브라우저 검사에서 빠진 파일은 그 행에 이유를 붙이고, 나머지 파일은 계속 처리한다.
- 실패 행에는 원인과 다음 행동 버튼(가이드 열기 · 다시 시도)을, 성공 행에는 결과 한 줄과 "틀렸어요"를 붙인다.
- 모든 파일이 끝나면 대시보드를 바로 그린다(`router.refresh()`). "결과 보기" 버튼을 찾게 하지 않는다.

### aha: 첫 대시보드
이탈 원인: 숫자를 믿지 못함.
- 총지출 바로 옆에 거래 건수 · 반영 기간 · 취소·환불 기준을 둔다. 사용자가 카드사 앱 숫자와 맞춰 볼 수 있어야 한다.
- 월간 요약은 총지출 바로 아래에 둔다. 총지출을 본 다음 이번 달을 한 문단으로 읽고, 근거 숫자(카테고리 · Top N · 확인이 필요한 지출)로 내려간다.
- 카테고리가 틀리면 그 자리("가장 많이 쓴 곳"의 가맹점 행, 나머지 가맹점은 펼쳐서)에서 고친다. 숫자가 바로 바뀌는 것이 "내 데이터"라는 감각을 준다.
- 확인이 필요한 지출은 숫자를 확인한 다음 순서에 나온다(아래 "계층 구조").

### 전환: 티저 → 업그레이드 모달 → 결제 — H3
이탈 원인: 가격 저항, "돈 낼 만큼인가".
- 업그레이드 진입점은 source 허용목록의 5곳(teaser · trend · summary · pricing · settings)뿐이다. 전역 배너·자동 팝업을 만들지 않는다. 모달은 사용자가 누를 때만 연다.
- 모든 진입점은 같은 업그레이드 모달을 연다. 모달 순서: 내 후보 건수·합계(Free DTO 값) → Pro에서 보이는 상세(정적 예시, 가짜 수치임을 밝힘) → 가격(KRW, 해외 $4.99/월) → 결제하기 · 닫기.
- 무엇이 보이게 되는지만 말한다. 절감액, 할인 타이머, 남은 시간, "지금 아니면"을 쓰지 않는다.
- 해지 방법을 결제 전에 한 줄로 밝힌다("설정에서 언제든 해지할 수 있어요. 남은 기간까지 Pro로 써요").
- 결제를 취소하면 원래 화면으로 돌아온다. 완료하면 "Pro가 활성화됐어요"와 함께 티저 자리에 상세가 나타난다. 반영 전이면 "결제 반영 중…"과 새로고침 안내(USER_FLOW ③).

### 습관: 월간 재방문 — H4
이탈 원인: 잊음(재방문 알림은 MVP 제외).
- 알림이 없으므로 재방문 동기는 화면 안에서 만든다. 상단 한 줄(월 선택기 · "N월까지 반영됨" · "새 이용내역 추가")은 늘 같은 자리에 둔다.
- 전월 대비는 "늘었어요/줄었어요" 문장으로 쓴다. 다음 달에 다시 와서 확인할 이유가 된다.
- 다시 올릴 때는 첫 업로드와 같은 흐름을 쓰되 반복을 줄인다: 기존 카드 라벨을 목록에서 고르고, 확인한 매핑은 다시 묻지 않는다(ADR-004).
- 기간이 겹쳐도 괜찮다고 알린다("겹치는 거래는 한 번만 반영돼요").

### 신뢰와 통제 (모든 단계)
- 데이터 고지(AI 전송 범위 · 원본 암호화 · 12개월 뒤 삭제 · 언제든 삭제)는 업로드 화면과 설정에서 같은 문장을 쓴다.
- 되돌리기는 결과 바로 옆(틀렸어요), 전체 삭제·탈퇴는 설정에 둔다. 탈퇴·삭제에 설문이나 반복 확인을 넣지 않는다(확인 문구 입력 1회).

## Figma 원칙 7가지 적용

### 1. 계층 구조
- 화면마다 읽는 순서를 정해 두고 지킨다.
  - 랜딩 히어로: 헤드라인 → 부제 → 데모 보기 → "로그인 없이 바로 볼 수 있어요" → 목업.
  - 대시보드: 월 · 반영 기간 → 월간 요약(전체 폭, 기간·건수·총지출을 코드가 채운 숫자로 먼저 말한다) → 총지출 · 전월 대비 / 카테고리 → Top N / 일별 → 확인이 필요한 지출(Free는 티저) → 추세(Free는 잠금 카드). 숫자를 확인한 뒤에 후보를 보여준다(원칙 2). 후보 상세는 여전히 숫자 뒤에 나온다.
  - 업그레이드 모달: 위 "전환"의 순서.
- 첫 뷰포트(375×667)에 그 화면 질문의 답이 들어와야 한다. 랜딩은 헤드라인과 데모 보기, 대시보드는 총지출과 반영 기간이다.
- 큰 숫자(`text-3xl`)는 카드 하나에 하나다. 나머지 금액은 목록 크기(`text-sm`)로 낮춘다.
- 고지·설명은 caption으로 낮추되 접거나 숨기지 않는다.

### 2. 점진적 공개
- 한 화면에서 한 가지 결정만 요구한다. 공개 순서: 랜딩(가치) → 데모(전체 화면) → 가입(구글만) → 업로드(파일·카드만) → 매핑 확인(처음 보는 형식일 때만) → 대시보드 → 업그레이드(가치가 가려진 자리에서).
- 가입 전에는 아무것도 입력받지 않는다. 카드 라벨은 첫 업로드 때 파일 옆에서 받는다.
- 진행 상황은 업로드 상태 행(대기 / 올리는 중 / 분석 중 / 확인 필요 / 완료 / 실패)으로 보여준다.
- Free → Pro는 건수·합계(Free) → 상세 예시(모달) → 실제 상세(Pro) 순으로 연다. Free 화면에서 상세를 흐리게 보여주지 않는다(DESIGN).

### 3. 일관성
- 같은 행동은 어디서나 같은 이름·모양·결과다.

| 행동 | 이름 | 결과 |
|---|---|---|
| 데모 진입 | 데모 보기 | `/demo` + `demo_click` |
| 가입 진입 | 무료로 시작하기 · 내 이용내역으로 해보기 | `/login` → 대시보드 |
| 업그레이드 진입 | Pro로 보기 (설정은 업그레이드, 랜딩 가격은 Pro 시작하기) | 항상 같은 업그레이드 모달 + source 기록 |
| 결제 | 결제하기 | 모달 안에서만 Polar checkout |
| 파일 추가 | 새 이용내역 추가 | 첫 업로드와 같은 흐름 |
| 되돌리기 | 틀렸어요 · 삭제 | 영향 고지 → 확인 |

- 용어는 아래만 쓴다.

| 쓴다 | 쓰지 않는다 | 이유 |
|---|---|---|
| 이용내역(승인내역) | 명세서, 거래내역, 청구서 | 받는 파일은 신용카드 이용내역뿐이다. 카드사의 "이용대금 명세서"는 청구서라서, "명세서"라고 쓰면 청구서를 받아 와 BILLING_STATEMENT로 실패한다(H2·H5) |
| 확인이 필요한 지출 · 후보 | 위험 지출, 낭비, 부정 결제 | 정상 지출일 수 있다 |
| 정기결제로 보여요 · 중복 결제 의심 | 구독 확정, 이중 결제 | 규칙 기반 추정이다 |
| 반영 기간 | 분석 기간 | 저장된 거래의 첫·마지막 이용일이다 |
| 카드(사용자 라벨) | 카드번호 | 번호를 받지 않는다 |
| 월간 요약 | AI 분석 결과 | "AI가 분석했어요"는 쓰지 않는다. AI를 쓴다는 사실은 요약 카드의 출처 한 줄로만 밝히고, 금액은 코드가 계산한다고 함께 쓴다(DESIGN "월간 요약 카드") |

### 4. 대비
- 화면 구역마다 가장 강한 대비는 다음 단계 하나에 준다.
- 의미별 색은 하나씩만 쓴다: primary = 다음 단계·완료, amber = 확인이 필요한 지출·mock, danger = 에러·되돌릴 수 없는 행동. amber를 업그레이드 유도에 쓰지 않는다.
- 삭제·탈퇴는 Primary로 만들지 않는다. 확인 모달에는 Destructive와 Secondary "취소"만 두고 Primary를 두지 않는다.

### 5. 접근성
DESIGN의 대비·포커스·색 규칙에 더해:
- 키보드만으로 랜딩 → 데모 → 로그인 → 업로드 → 업그레이드 모달까지 끝낼 수 있어야 한다.
- 파일 선택은 라벨이 붙은 `<input type="file" multiple>`이 기본이고, 드래그 앤 드롭은 보조다.
- 상태 변화(업로드 상태 · 카테고리 저장 · 결제 반영)는 `aria-live="polite"` 영역으로 알린다. 파일별 에러는 그 행에 붙인다.
- 모달은 열리면 패널 안으로 포커스를 옮기고, Esc로 닫히며, 닫히면 연 버튼으로 포커스를 돌린다.
- 버튼 높이는 44px(`h-11`)가 기본이다. 행 안 작은 버튼(`h-9`)은 서로 8px 이상 띄운다.
- 랜딩·데모는 375px 폭에서 가로 스크롤 없이 끝까지 볼 수 있어야 한다. SNS·지인 공유 유입은 휴대폰에서 시작한다.

### 6. 근접성
- 행동과 설명은 그것이 다루는 정보 바로 옆에 둔다.
  - 데이터 고지 ↔ 파일 선택 버튼, 카드 선택 ↔ 각 파일 행, "틀렸어요" ↔ 결과 요약
  - 거래 건수·반영 기간 ↔ 총지출, "정상 지출일 수 있어요" ↔ 후보 합계
  - "Pro로 보기" ↔ 가려진 가치(티저 · 잠금 카드 · 요약) 바로 아래, 가격 ↔ Pro에서 얻는 것 목록
- 위험한 행동은 떼어 둔다. 설정의 전체 삭제·탈퇴는 맨 아래 별도 구역(`space-y-12`)에 두고, 업로드 내역과 섞지 않는다.

### 7. 정렬
- 왼쪽 정렬이 기본이다(DESIGN). 이름은 왼쪽, 금액은 오른쪽 `font-mono`인 행 패턴을 카테고리 · Top N · 후보 · 업로드 결과에 똑같이 쓴다.
- 카드 안의 제목 · 큰 숫자 · 보조 줄은 같은 왼쪽 선에 맞춘다.
- 모달 버튼은 모바일에서 전체 너비로 쌓아 Primary를 위에, `sm:` 이상에서는 오른쪽 정렬로 Primary를 오른쪽 끝에 둔다.

## 프로 팁 4가지 적용
1. **관점 먼저**: 화면·컴포넌트를 만들기 전에 (여정 단계, 사용자 질문, 다음 단계)를 한 줄로 정한다. step 파일에 없으면 "상태별 다음 단계" 표에서 찾는다.
2. **단순하게, 피드백은 분명하게**: 모든 행동은 누름 상태(120ms) → 처리 중(스피너·스켈레톤) → 결과(완료 문구 또는 원인 + 다음 행동) 순서로 반응한다. 조용히 실패하지 않는다.
3. **단축**: 월 1~2회 쓰는 도구라 키보드 단축키는 만들지 않는다. 대신 반복을 줄인다: 여러 파일 한 번에 올리기, 카드 라벨 재사용, 확인한 매핑 기억, 카테고리 수정의 같은 가맹점·다음 업로드 적용, `?month=`로 월 북마크.
4. **테스트**
   - 지표: H1~H5가 나쁘면 아래 화면부터 본다.

     | 지표 | 먼저 볼 곳 |
     |---|---|
     | H1 데모 클릭률 | 히어로 헤드라인 · 데모 보기 대비 · 첫 뷰포트 |
     | H2 첫 업로드 성공률 | 카드사 가이드, `upload_attempts`의 실패 단계·코드별 문구 |
     | H3 클릭 → 결제 | source별 전환, 모달 순서 · 가격 표시 · 티저 문구 |
     | H4 재방문 | 상단 반영 기간 · 새 이용내역 추가 위치 |
     | H5 24시간 내 삭제 · UNREADABLE | 결과 요약 한 줄, 매핑 확인 화면 |
   - 사람: 배포 후 5명에게 자기 카드 파일로 첫 업로드를 시키고 말없이 관찰한다(파일을 어디서 못 찾는지, 청구서를 받아 오는지).
   - 코드: 테스트할 수 있는 UX 규칙은 Testing Library로 단언한다. 다음 단계 버튼의 이름·링크, 에러에 붙은 행동 버튼, 상태 영역의 `aria-live`, 금지 문구가 없음.

## 문구
- CTA는 결과가 보이는 동사로 쓴다: 데모 보기, 무료로 시작하기, 파일 선택, 이대로 읽기, Pro로 보기, 결제하기. "확인"·"다음"·"제출"만 단독으로 쓰지 않는다.
- CTA 아래 caption 한 줄로 불안을 덜어 준다.

| CTA | 아래 한 줄 |
|---|---|
| 데모 보기 | 로그인 없이 바로 볼 수 있어요 |
| 무료로 시작하기 | 구글 계정으로 시작해요. 카드번호는 받지 않아요 |
| 파일 선택 | 원본 파일은 암호화해 보관해요 |
| 결제하기 | 설정에서 언제든 해지할 수 있어요 |

- 쓰지 않는다: "지금 바로", "놓치지 마세요", "마지막 기회", 남은 시간 표시, "~원 아끼세요", 느낌표(DESIGN "문구").

## 화면 체크리스트
step에서 화면을 만들거나 바꾼 뒤 확인한다.
- [ ] 이 화면의 여정 단계 · 사용자 질문 · 다음 단계를 한 줄로 말할 수 있다
- [ ] 다음 단계가 화면에서 가장 눈에 띄고, Primary는 구역당 한두 개 이하다
- [ ] 375×667 첫 뷰포트에 질문의 답이 보인다
- [ ] 빈 상태 · 처리 중 · 에러 · 완료 상태가 있고, 에러에는 다음 행동이 붙어 있다
- [ ] 숫자 옆에 근거(반영 기간 · 건수)가 있다
- [ ] 업그레이드 진입은 가치가 가려진 자리에만 있고 source가 붙는다
- [ ] 용어표와 금지 문구를 지킨다
- [ ] 키보드로 끝까지 진행되고, 상태 변화가 `aria-live`로 알려진다
