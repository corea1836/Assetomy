# 의도적으로 뺀 것 (다시 넣지 말 것)

ADR을 정하며 뺀 장치와 대신 하는 것이다. 실행기가 매 step 프롬프트에 붙인다. 새로 뺀 것은 이 표에 더한다.

| 항목 | 대신 하는 것 |
|---|---|
| 범용 `events` 테이블 | Vercel Analytics + `user_metrics`·`upload_attempts` |
| 실제 셀 값(행 샘플) 전송·마스킹, 매핑 실패 시 LLM 재시도 | 헤더 + 값 패턴만 전송, 실패는 UNREADABLE(ADR-004) |
| Storage signed URL 직접 업로드, 4MB 초과 파일 | 서버 직접 수신 + 암호화(ADR-007) |
| 업로드 횟수 차감, '다시 분석' 버튼 | 운영 한도 + 요약은 `input_hash`로 자동 갱신 |
| 카테고리 추가·이름 변경 | 고정 14개 + 가맹점 수정(ADR-017) |
| `data_generation`(데이터 세대), `user_operations` 테이블 | 사용자별 advisory lock + 업로드 행 존재·그 달 거래 존재 검사. 24시간 한도는 `upload_attempts`로 센다(전체 삭제·탈퇴 시 초기화 수용) |
| 업로드 생성과 파일 전송 분리(pending), 202 처리 중·상태 폴링, `GET /api/uploads/[id]` | 요청 하나로 수신·처리. 응답을 못 받으면 같은 파일 재업로드(file_hash·fingerprint로 이중 저장 없음) |
| 매핑 열 직접 수정, 클라이언트가 보낸 매핑 | "이대로 읽기"/취소만, 서버가 저장한 제안만 확정(ADR-004) |
| 폴백의 상태 표시형 취소 해석, LLM의 취소 방식 추정 | 음수 금액 취소만, 나머지는 UNREADABLE(ADR-004) |
| 연도 없는 날짜, 다운로드 기간 입력 | 연도가 있는 형식만(`year_required`) |
| 1시간 주기 결제 상태 보완 동기화 | 기간이 지난 상태만 재동기화 |
| 파일 전송 실패 기록 | 서버가 받은 요청부터 측정 |
| 제외 사유별 집계(SkipBreakdown) | `skipped: number` 하나 |
| 세분화된 업로드 에러 코드 | 업로드 코드 5개 + 허용된 reason + HTTP 상태 |
| `/api/summary` 라우트와 클라이언트 fetch | 대시보드 Server Component에서 생성(Suspense) |
| `documentType` 3값 | 청구서 여부 boolean 판별 |
| 식별자 없는 형식의 폴백·기간 겹침 판정 | 거래별 식별자가 있는 형식만 지원. 예외는 검증된 프로필의 내용 키(ADR-006·019) |
| PDF OCR·PDF 폴백 매핑·LLM으로 PDF 읽기 | 글자 추출 가능한 PDF + 프로필 + 명세서 금액 대조(ADR-019) |
| 처리 자동 재claim·claim 세대 번호 | lease 만료 시 failed 종료 + 재업로드(ADR-008) |
| `deleting` 상태·삭제 작업 테이블·Storage 폴더 커서 | DB 즉시 삭제 + 고아 정리(ADR-009) |
| 결제 동기화 lease·세대 번호 | 조회 시작 시각 조건부 저장(ADR-012) |
| `data_revision` 읽기 전후 비교 | 요약은 `input_hash`로 신선도 판단 |
| `ai_summaries`의 Pro 전용 RLS, Storage 사용자 select 정책 | 본인 select만 / 정책 없음 |
| 데이터 없는 월 → 가장 가까운 월 리다이렉트 | 기본 월(최근 데이터 월)로 대체 |
| "이 달에 반영된 파일 n개" 표시 | 거래일 범위와 부분 데이터 안내 |
| UTF-16 CSV | UTF-8 → EUC-KR만 |
| 같은 청구서 재업로드를 거래 단위로 맞추기, 나중에 올린 파일이 무조건 이기기 | 청구서 단위 교체 + PDF 저장 시각 비교(ADR-023) |
| 카드 번호·끝 4자리 입력, 상품명으로 카드 자동 선택·생성 | 카드사·이름으로 등록한 카드를 사용자가 고르고, 카드사·상품명이 다르면 거절(ADR-023) |
| 카드 탭의 탐지·추세, 거래를 이용 기간으로 다시 묶기, 카드사 수정 | 탐지·추세는 전체 탭에만, 명세서(결제일) 단위로 묶고 이용 기간은 표시·완료 판단에만, 카드사는 등록 때 고정(ADR-024) |
| 가맹점 메모(가맹점마다 사용자 설명) | 팁의 카테고리마다 피드백 하나(ADR-025) |
| 흐름을 LLM이 판단, 흐름 차트 | 코드가 정한 흐름 라벨을 카드 요약 입력에만(ADR-025) |
| 기간을 넘는 취소·부분 취소 짝 맞추기 | 같은 기간·카드·가맹점의 정확히 반대 금액만 짝(ADR-025) |
